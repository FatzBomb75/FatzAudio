# Engineering notes

Known issues and follow-up work that were found while doing something else and
kept out of that change so it stayed small. Add new entries at the top. When an
item is fixed, delete its entry in the same change and mention the PR there.

Each entry has a date, the area it touches, what's wrong or missing, and where it
was found (a PR, a review, or a thread).

| 2026-10-18 | bass-compare/AAC | 16 AAC streams now take 119 KB each from `.aac` and 158 KB from `.m4a` under Wine (235 and 242 before PR 47; bass_aac 50 and 63 KB): blocks are mixed straight into the output (the decoder kept a 64 KB 7.1 buffer), the windows and tables are shared, AAC LTP's work buffers are allocated only for LTP, quantized values are read into one buffer per decoder, and the ADTS index keeps every 16th frame. | 2026-10-18 | bass-compare/Vorbis, WAV | Vorbis now decodes faster than BASS under Wine (median of 10 runs on the 30 s q5 file: 46 ms, 647× real time, against BASS's 70 ms; 63 ms before) with FatzAudio's MDCT in libvorbis (PR 45). 16 Ogg Vorbis streams take 240 KB each against BASS's 187 KB (286 before PR 46, which stopped the Ogg reader keeping its own parsed copy of the Vorbis setup, about 35 KB, and sized its packet queue to the page). | 2026-10-18 | bass-compare/Dolby | A unit of one syncframe (every AC-3 stream, and E-AC-3 with a single substream) is mixed block by block straight into the interleaved output (PR 44). Under Wine, 16 AC-3 5.1 streams take 121 KB each (168 before PR 44, 131 before PR 46; bass_ac3 67 KB), one stream alone 88 KB (bass_ac3 140 KB). Left as is, as not worth its risk: the decoded unit handed to the track, 36 KB for 5.1 (1536 frames of 6 floats). Decoding one 256-frame block per call would make it 6 KB but needs a codec interface that hands out part of a packet, and a syncframe whose CRC fails at its end would then already have played its first blocks. The rest is the per-stream state every format has (about 22 KB) and the file read-ahead (16 KB). E-AC-3 with more substreams (7.1, several programs) still uses the per-speaker unit buffers. | BASS comparison thread |
| 2026-10-17 | Dolby | Where FFmpeg 6.1's E-AC-3 decoder differs from TS 102 366 V1.4.1 (FatzAudio follows the spec; the test streams avoid these, and FFmpeg is not a reference there). AHT: its hebap 4 vector table is one row off (Table E.3.4), it dithers zero-bit bins whatever dithflag says, and it redoes the coupling channel's bit allocation in blocks 1 to 5. Block-level SNR offsets: it reads the per-block flag only in block 0. Fast gains: it keeps a block's previous values where the spec resets them to the default (including the coupling channel's when coupling starts mid-frame). Enhanced coupling (which FFmpeg doesn't decode) is tested by streams that code the same audio with standard coupling. | AHT and enhanced coupling PR |
